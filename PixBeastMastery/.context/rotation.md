# PixBeastMastery 循环与思路

依据当前 [rotation.py](../pix/rotation.py) 整理。字段含义见 [layout.md](layout.md)，动作绑定见 [keymap.md](keymap.md)。

## 循环思路

核心 DPS 优先级与打断、自保、宠物管理分别说明。每轮执行首个满足条件的动作。

## 函数结构

`main_rotation` 依次调用 `check_pause(ctx)`、`precombat_rotation(ctx)`、`defensive_rotation(ctx)`、`interrupt_rotation(ctx)`，然后选择 `main_target`、检查设置焦点，计算 `is_aoe` 和 `is_finishing`，调用 `aoe_rotation(ctx, main_target, is_finishing)` 或 `single_target_rotation(ctx, main_target, is_finishing)`。分类方法未匹配返回 `None`；返回任何动作，包括 `Idle`，都立即结束本轮。

`precombat_rotation` 每轮处理宠物恢复、脱战误导和战斗门控，不检查当前目标。自保与打断不依赖有效主目标。主目标选择与设置焦点均在入口实现，单体和AOE继承主目标射程门控，不再单独检查当前目标射程。输出方法返回 `None` 后，入口检查治疗宠物。

主目标每轮从 `None` 开始，按焦点→当前目标选择。两者均严格检查存在、可攻击、不可协助及反制射击射程内四项，不额外检查存活。均不合格时返回 `Idle("无有效目标")`，不再执行输出或治疗宠物。主目标为 `target` 且焦点不存在时，返回 `Cast("设置焦点")`，宏为 `/focus [@target,exists]`；本轮结束，下一轮重新选主目标。已有焦点即使不合格也不覆盖，可以回退攻击合格的当前目标。

倒刺射击、狂野鞭笞、杀戮命令、眼镜蛇射击的全部分支使用 `target技能名`／`focus技能名` 动作，宏显式指定主目标。狂野怒火保留原动作名与键位，宏先执行 `/target focus`，再执行 `/cast 狂野怒火`；不追加切回原目标的命令。药水、饰品及宠物技能保留原动作。

## 状态与动作优先级

每次只执行第一个满足条件的动作。启停、手动延迟、死亡、坐骑/载具、聊天、地面选点和施法/引导/蓄力会暂停自动动作。

1. **恢复宠物**：缺宠或死宠时，移动则等待站定，站定后执行召唤/复活宏；位于战斗和目标判断之前。
2. **自动误导**：只在非团队小队、脱战时执行。要求学会误导、冷却好。先按 party1–4 取第一位存在、存活且在线的坦克，再检查该坦克是否在误导射程内；超距不改选后续坦克，不要求攻击目标，冷却好就可再次释放。
3. **战斗门控**：此后的打断、自保、主目标选择、设置焦点、输出和治疗宠物均要求玩家在战斗；自保和打断不要求有效主目标。
4. **自保**：生命≤30%先治疗石，再银月城生命药水241304；生命≤50%时意气风发。自保优先于打断，其他防御技能由玩家控制。
5. **反制射击**：自保未命中后，按目标、焦点、鼠标指向顺序判断；自身冷却好、单位存在、存活、可攻击且不可协助、在射程、可打断、图标不在黑名单，且已过施法进度严格大于配置阈值。鼠标指向与目标打断还受各自开关控制。
6. **主目标与设置焦点**：按上述规则选择主目标；无有效主目标则等待，无焦点且主目标为target则设置焦点并结束本轮。
7. **爆发药水**：爆发窗口内、主目标在反制射击范围、药水开关开启且第54格就绪时使用共用爆发药水宏，依次尝试狂放恣意饮剂241293、241292，再尝试鲁莽药水241288、241289。任一物品有库存、冷却启用且已结束即就绪；不新增独立检测格或宏。
8. **输出**：按下面的优先级执行，所有进攻技能都参考反制射击147362射程。
9. **治疗宠物**：最低优先级；宠物存在、存活、生命<70%，且治疗宠物冷却好。脱战或没有有效主目标时不执行；主目标射程也是此处的前置条件。

敌人数只统计可观察姓名板中可攻击、存活、进入战斗且在147362射程内的单位，不代表所有附近敌人。自动模式人数≥2走AOE，0或1走单体；强制模式覆盖此判断。

| 顺序 | 输出条件 | Cast 理由 |
| --- | --- | --- |
| 1. 倒刺射击 | 倒刺充能≥2 | 满层，避免浪费 |
| 2. 倒刺射击 | 倒刺充能≥1、下一层恢复≤4秒 | 即将满层，避免浪费 |
| 3. 倒刺射击 | 倒刺充能≥1、怒火冷却≤4秒且未收尾 | 即将由狂野怒火获得充能，避免浪费 |
| 4. 狂野怒火 | 怒火冷却为0且未收尾；AOE额外要求顺劈剩余≥2秒；先检查自动饰品 | 狂野怒火CD好 |
| 5. 狂野鞭笞 | 仅AOE：鞭笞冷却为0、集中值≥35 | 卡CD打 |
| 6. 杀戮命令 | 满足下述杀戮共同条件，且猎群领袖之嚎存在 | 猎群领袖之嚎高亮 |
| 7. 杀戮命令 | 满足下述杀戮共同条件，且自然之友存在 | 自然之友高亮 |
| 8. 眼镜蛇射击 | 集中值≥35、利牙层数>3；AOE额外要求顺劈剩余≥1秒 | 4层利牙 |
| 9. 倒刺射击 | 倒刺充能≥1 | 兜底倒刺 |
| 10. 眼镜蛇射击 | 集中值≥35；AOE额外要求鞭笞冷却>1秒 | 兜底眼镜蛇 |

单体跳过第5条，其余按表中顺序执行。倒刺和杀戮均以充能判断可用，不额外检查自身冷却。上表均继承战斗、有效主目标和射程门控。

倒刺恢复与怒火提前判断包含恰好4秒；AOE怒火的顺劈条件包含恰好2秒，利牙眼镜蛇及杀戮的顺劈条件包含恰好1秒。利牙恰好3层不满足优先眼镜蛇条件，4层满足；AOE兜底眼镜蛇在鞭笞冷却恰好1秒时不满足。条件按解码后的数值比较，不另加容差。

自动饰品仅在到达单体或AOE的怒火分支、满足该分支全部条件时检查，不要求爆发窗口。开启自动饰品后，优先使用可用上饰品，其次可用下饰品；关闭自动饰品或无可用饰品时直接释放怒火。每轮只执行一个动作，下一轮重新判断全部条件，不等待饰品冷却，也不锁定后续怒火。前三条倒刺规则优先于饰品；收尾、怒火冷却未好或AOE顺劈不足2秒时不会自动使用饰品。

首领战等同于第86格的遭遇战状态，自动模式在遭遇战中始终不收尾。非遭遇战时使用主目标预测生命比例，每轮判断是否严格低于配置阈值；恰好等于阈值不收尾，切换主目标或血量恢复后重新判断。集中值百分比由配置上限还原；配置错误会影响35点阈值判断。缺失冷却数据不视为就绪；满充能通过充能数量及上限识别。

## 专属约定：杀戮命令

两段循环均要求杀戮充能≥1、集中值≥35，且不满足“怒火即将就绪且杀戮充能恰好1层”。怒火即将就绪定义为怒火冷却≤4秒且未收尾；此时保留最后1层杀戮充能，2层仍可使用。收尾时不为怒火保留充能。AOE还要求顺劈剩余≥1秒；单体不检查顺劈。

满足共同条件后，先判断猎群领袖之嚎，再判断自然之友1276720，分别记录高亮理由；两者同时存在时优先记录猎群领袖之嚎。猎群领袖之嚎并非独立光环，以飞龙471878、猪472324、熊472325三种互斥形态呈现，第55格统一判断任一种是否存在。杀戮不额外限制利牙层数；两条杀戮分支均优先于4层利牙眼镜蛇，后者位于兜底倒刺之前。

## 专属约定：鞭笞、怒火与眼镜蛇

AOE怒火要求顺劈剩余≥2秒；鞭笞排在怒火之后，要求冷却为0且集中值≥35。循环不使用怒火施放后4秒窗口，也不以顺劈或怒火增益的存在布尔值判断输出。单体不施放鞭笞，怒火不要求顺劈。

优先眼镜蛇要求利牙>3层且集中值≥35，AOE还要求顺劈剩余≥1秒，单体不要求顺劈。该分支不检查鞭笞冷却。最后的兜底眼镜蛇要求集中值≥35，AOE额外要求鞭笞冷却严格大于1秒，为即将就绪的鞭笞保留资源；单体没有此限制。

用户经验：用户反馈利牙层数在眼镜蛇弹道命中后才消耗，期间外部循环可能重复选择眼镜蛇，挤占杀戮命令。因此单体和AOE均让两条高亮杀戮优先于4层利牙眼镜蛇，减少利牙延迟消耗对杀戮选择的影响。此前“两种顺序区别不大”的反馈不再作为保留眼镜蛇优先的依据。本次仅调整优先级，不加入防重复机制，也不保证消除所有眼镜蛇连发；实际改善需游戏内观察，未提供量化收益数据。

## 三态收尾与血量阈值

第60格使用配置枚举，灰度0自动、10残血持续爆发（关闭收尾）、20残血不爆发（开启收尾）。`Context.finishing` 返回整数模式，`main_rotation` 在进入输出分支前计算局部变量 `is_finishing` 并传入输出方法，单体与AOE的狂野怒火均要求该变量为False。

- 自动（默认）：首领战等同于第86格 `encounter_in_progress`，遭遇战中始终不收尾；否则，按 `main_target` 读取焦点的 `focus_health_pct` 或当前目标的 `target_health_pct`，主目标预测生命比例严格低于第87格 `finishing_health_threshold` 时收尾。异常模式值按自动处理。
- 残血持续爆发（关闭收尾）：始终不收尾，狂野怒火仍按原有施放条件使用。残血不爆发（开启收尾）：名称仅为显示文案，实际仍始终收尾，包括遭遇战中；两者均不受血量阈值影响。
- 阈值默认20%，范围0–50%，滑块步进5；恰好等于阈值不收尾，0表示自动模式不收尾。每轮重新判断，切换主目标、血量恢复不会保留此前状态。
- 收尾禁止狂野怒火及其前置自动饰品，同时关闭怒火前提前倒刺和杀戮保留最后1层的条件；不影响药水、满层倒刺及恢复≤4秒的倒刺规则。
- 模式脱战、重载恢复自动，阈值与按钮位置持久化保存。按钮及 `/pix end toggle` 按自动→残血持续爆发→残血不爆发循环，`/pix end auto|off|on` 可直接指定。

第87格用灰度字节直接表示阈值，Python四舍五入读取，超出0–50回退20，合法的0保留。当前基板包含第88格，宽360px，插件与Python必须配套更新。

## 状态读取

第55格通过单个AuraSlot同时匹配飞龙471878、猪472324、熊472325，任一种存在为白色，否则黑色；`Context.player_has_buff_howl_of_the_pack_leader`读取该格。第57、58格留空，不再加载旧形态cell，后续编号和360×12基板不变。插件和Python须配套更新，执行`/reload`并重启Python，验证三种形态出现、切换和消失。

第88格监控玩家成功施放狂野怒火19574后的本地4秒窗口，通过`Context.bestial_wrath_cast_remaining`读取剩余秒数。只监听player的`UNIT_SPELLCAST_SUCCEEDED`，可读法术ID匹配后启动或重置4秒；秘密、缺失或其他ID忽略且保留已有计时，不回退冷却事件。插入打断、其他技能、切目标和脱战均不清除窗口；初始化、重载和进入世界清零。使用截止时间计算，每0.1秒刷新，灰度字节为剩余秒数乘10向上取整，Python除10还原；量化高估小于0.1秒，显示另受刷新和卡顿影响。这不是怒火增益剩余时间；保留采集与解码，当前循环不使用。更新插件后执行`/reload`并重新定位360×12基板；战斗中事件ID的可读性需实机确认。

第 59 格通过 AuraContainer 的 SetApplicationCount 绑定共享 CountFormatter，显示玩家眼镜蛇利牙1299389层数。`Context.player_buff_stacks_cobra_fangs`按灰度字节四舍五入读取整数，0包含无光环或无计数，255表示至少255层；`player_has_buff_cobra_fangs`由层数大于0派生。当前循环以利牙>3触发优先眼镜蛇，AOE还要求顺劈剩余≥1秒；单体不要求顺劈，杀戮不限制利牙层数。第59格由布尔改为计数，插件与Python必须配套更新，更新插件后执行`/reload`并重启Python；基板尺寸不变。

第 76 格通过原生 AuraContainer 显示玩家野兽顺劈：存在为白色，不存在为黑色。Python 通过 `Context.player_has_buff_beast_cleave` 读取，插件与 Python 必须配套更新。

第 84 格以相同方式显示玩家狂野怒火增益 19574，通过 `Context.player_has_buff_bestial_wrath` 读取。更新插件后需在游戏内 `/reload`，并让 Python 重新定位扩展后的基板。

第 85 格通过 AuraContainer 的 DurationText 原生绑定和 `AuraRemaining` 曲线显示玩家野兽顺劈剩余时间，由 `Context.player_buff_beast_cleave_remaining` 解码为秒。0 表示不存在或到期，240 包含永久光环或上限饱和；实际阈值判断受渲染与采样影响。
