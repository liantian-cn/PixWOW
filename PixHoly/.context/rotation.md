# PixHoly 循环与思路

依据当前 [rotation.py](../pix/rotation.py) 整理。字段含义见 [layout.md](layout.md)，动作绑定见 [keymap.md](keymap.md)。

## 循环思路

只维护玩家和 party1–4 的五人治疗循环；团队中仍只处理这五个单位。先筛选有效成员并计算生命评分，再按优先级选人。定向宏不切换当前目标，不引入通用 JSON 解释器或40人宏展开。

## 状态与门控

插件关闭、延迟中、死亡、骑乘／载具、输入或地面选点时等待。首领索引100且任一前两位首领已过施法时间≥4秒时，若自己施法或蓄力则停止施法，否则等待。引导和蓄力直接等待；普通读条剩余>0.4秒时等待，最后0.4秒可以选择下一技能。

候选成员须存在、存活、在线、可协助、在治疗范围且没有救赎之魂。治疗与驱散参考圣光术82326范围；敌对输出参考制裁之锤853范围。

生命评分 = 基础评分 − 治疗吸收百分比。普通成员的基础评分为预测生命百分比；血 DK 以死亡骑士职业（class_id=6）且坦克职责（role=1）识别，预测生命百分比 h 按以下规则转换为基础评分：

- h ≤ 1：保留 h。
- 1 < h < 80：使用 `1 + (h - 1) * 99 / 79`。
- h ≥ 80：按 100 计算。

例如无治疗吸收和读条预估时，血 DK 的 1%→1、40%→约49.87、60%→约74.94、80%→100、85%→100；输出职责 DK 和其他职业仍使用原始预测生命百分比。80% 及以上仍扣除治疗吸收，例如 85% 血量、30% 治疗吸收且无读条预估时，最终评分为 70。

先转换基础评分，再减治疗吸收百分比。普通读条期间，已知读条目标再加圣光术40或圣光闪现15，预估数值不参与血量映射；这两种读条还预估增加1圣能。最终评分不封顶、不保底，统一用于所有治疗选人和受伤人数统计，包括脱战及首领特殊治疗。最低成员可为负评分，受伤人数只统计评分严格大于0且严格小于阈值的成员；伤害吸收不加入评分。

动态阈值：圣光术为 `int(法力百分比−25)`；灌注闪现为 `int(100−灌注剩余秒数)`；神性圣光为 `int(100−2×神性之手剩余秒数)`。最低成员筛选使用严格小于阈值。

## 专属约定

荣耀圣令宏在学会永恒之火时使用永恒之火，否则使用荣耀圣令。驱散按类型和成员枚举顺序选择，不按最低血量排序。除明确要求战斗的分支外，治疗可以脱战执行。没有自动打断或通用插入技能逻辑。
