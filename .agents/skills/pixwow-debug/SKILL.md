# PixWOW 排错

先读 [共用规范](../pixwow-rotation-develop/references/project-rules.md)。从实际代码和已有日志查明项目、故障层级、触发状态与近期变更，只询问环境中无法发现的复现条件、预期行为和运行证据。

## 按症状追踪链路

| 症状/入口 | 检查证据 |
| --- | --- |
| 格子不出现、更新慢或状态残留 | 插件目录和 TOC、Lua 错误、初始化顺序、事件、周期兜底、单位换绑、光环移除、显示层级及清空路径。 |
| 定位失败或区域错误 | `capture.py` 的截图结果/返回码、窗口与桌面边界、缩放、检测格、基板尺寸；必要时运行现有 `pix.test_captura`，它只检查截图定位且不发键。 |
| 属性值错误 | Lua 原始显示与 Matrix 实际采样区域、颜色顺序、量程、曲线、舍入、ValueBar/图标解析，再检查 Context 属性。按需执行像素一致性审查。 |
| 不出动作或选错技能 | 当前帧的 Context、最早命中的门控和规则、外层条件、派生过滤、目标/焦点/小队顺序及配置；先读 rotation.md，不直接调整优先级掩盖数据错误。 |
| 已选动作却没有游戏效果 | Action 日志阶段、截图帧有效性、调度与 Sleep、动作名、keymap、Keyboard 目标窗口和发送结果、Lua 宏绑定/目标；区分返回动作、发送按键、游戏成功施法。 |

沿最早出现偏差的层级缩小范围，记录“输入/状态→预期→实际→源码原因”。不能把单次旧帧或图标未知误判为循环错误；也不能认为每个项目的门控和黑名单规则相同。

涉及像素编码、秘密值、光环绑定或刷新机制时，实际读取 wow-pixel-encoding 的 SKILL.md 与相关 reference；涉及 API/事件行为时查本地 wow-ui-source 的定义和调用方，按共用规范核对版本。编码技能不负责本项目的截图定位和发键诊断。

## 修复与验证

用户只要求分析时提供原因和最小修复建议；请求修复时在原因确定后修改，遵循根 AGENTS.md 的确认和提交规则。证据不足时保留假设，列出下一项能区分假设的检查，不盲目添加日志、轮询或异常吞噬。

复用现有静态检查和诊断工具。检查需求涉及实机时才运行相应诊断，不能为了静态排错自动启动完整循环或发送动作。无法访问游戏现场时明确需要用户验证的状态转换，不声称复现或修复已获实测证明。

修复像素协议时同步 Lua、Python 和布局文档；修改 rotation 业务逻辑时按 [rotation 开发](../pixwow-rotation-develop/SKILL.md) 完成注释、相关文档及独立审核。只在已明确故障且确有必要时新增少量回归案例。

最终说明原因、证据、修改或建议、实际完成的检查及剩余限制；不新增验收报告。
