# Lua 与 Python 像素协议审查

先读 [共用规范](../pixwow-rotation-develop/references/project-rules.md)。比较选中项目自身的 Lua 与 Python，不将所有项目都与 PixBlood/context.py 对照。涉及编码语义或 API 时按共用规范读取 wow-pixel-encoding 和上游源码。

## 建立实际布局

1. 从 TOC、初始化顺序和 `core/base.lua` 追踪已加载的 cells、UI 工厂、尺寸、基板宽度及检测格。文件前缀仅作为入口，以构造参数和运行时循环展开结果为准。
2. 对每个输出建立临时核对表：生产者、单位、坐标/区域、占用跨度、编码/量纲、刷新来源、Python 消费者。表可在工作分析或回复中使用，不保存验收文件。
3. 展开共享 helper：尤其 PixHoly 的 `core/units.lua`、player/party1–4 顺序、批量四格字段、吸收条起点与步长。检查 ValueBar 内容宽度与额外分隔占位；IconTile 索引和 Cell 坐标不共用同一几何公式。
4. 从 `context.py` 追至 `matrix.py` 及必要的 capture 色彩转换，核对真实采样区域、物理/UI 缩放、通道顺序、越界、重叠和未加载输出。输出没有 Python 消费者或字段别名不必然是错误，先确认用途。

## 对照编码语义

- 布尔的真/假颜色与 Python 判定；按[项目解析约定](../../../.context/wow-api-notes.md)核对异常输入。当前非白返回 false 是明确设计，不建议擅自改为三态或抛异常。
- 比率、百分数、整数灰度、枚举、计数缩放、时间单位与舍入；名称带 count 不代表字节直接等于数量。
- Lua 曲线节点与 Python 反插值逐项配对；核对零点、每个折点、中间段、上下界与饱和。不要把冷却纯白“就绪”和光环纯白“永久或饱和”混为一谈。
- ValueBar 的有效黑白区域、量程和分隔；当前分母为零返回 0 是吸收量的设计兜底。图标核对同一客户端不同位置的裁剪、哈希及空图标，不要求跨客户端指纹一致，也不能假定纹理唯一对应技能 ID。
- 不存在单位、nil、光环移除、永久光环、满充能及目标切换的含义和清空行为。区分原始字段与 Context 派生规则，例如带黑名单的可打断状态。
- 实际刷新链路满足最长 1 秒兜底，并识别原生 AuraContainer 豁免。事件回调和配置回调不算周期刷新，已有更快共享轮询无需重复添加。

## 结论

报告具体 Lua 生产位置与 Python 消费位置、预期值和实际解码差异、影响及建议。位置一致但刷新缺失属于规范缺口，应与编码错配分开描述。文档差异交叉引用 [文档审查](../pixwow-docs-audit/SKILL.md)，不重复扩展为全项目重构。渲染精度、秘密值运行状态和游戏事件实际行为须标明实机验证限制。
