# 独立 Rotation 审核

先读 [共用规范](../pixwow-rotation-develop/references/project-rules.md)。本 skill 明确要求委派一个独立只读 subagent，不由实现者的自查替代。

## 主 agent：准备与委派

确定项目、用户确认需求和审核范围。开发后审核以本次 diff 及相关依赖为范围；单独要求项目循环审核时覆盖当前完整循环。工作区 diff 为空不代表无需审核：根据任务读取已提交变更或当前实现。无法确定比较基准且影响结论时先询问。

使用可用的 subagent 工具创建审核者，不覆盖模型设置。尽量使用不继承完整对话的上下文，明确给出：

> 你是本次独立只读审核者。阅读根 AGENTS.md、本 skill、共用规范和指定项目的 README、rotation/layout/keymap 文档。下面提供的是用户确认需求与审核范围。自行读取实际源码和 diff，检查规则正确性、注释、Lua 职责及刷新，并追踪必要的解码和宏。不要编辑、提交、启动游戏、发送按键或再次委派。按严重程度返回有位置与证据的发现，区分本次问题、历史问题和待验证项；无发现也说明覆盖范围与验证限制。

明确要求 cells 文件头风格专项审计时，以该专项为范围，逐文件覆盖指定 cells 目录下全部 Lua；按项目委派只读子代理，记录文件清单、问题位置及动态访问例外，不自动扩展为功能审计。其他明显问题单独备注。主 agent 对照目录清单核实覆盖完整性，报告交付形式遵循用户要求。

附上实际需求、项目路径、比较基准或文件范围；不把实现者的分析结论或“应当通过”作为审核前提。单独审查默认不修复，开发任务中的修复由主 agent 处理。

## 审核者：核对重点

- **cells 文件头：** 按[Lua cells 文件头规范](../../../.context/code-quality.md#lua-cells-文件头)检查分段顺序、声明归类、稳定引用本地化、统一段注释和段间空行。追踪动态状态、延迟初始化对象的赋值依据，不把运行状态就近声明或对象方法调用误判为违规。
- **业务与规范：** 每个业务条件前的“如果/=>”说明是否准确、完整；包含嵌套目标选择、辅助函数和筛选表达式。检查首个返回、外层门控、边界、资源、充能、施法/引导、爆发、目标有效性与范围、不可达或覆盖分支。没有确认依据时不凭个人打法宣判策略错误。
- **动作链：** Context 的字段含义和派生条件、动态动作名、键位、宏目标和 Action 执行是否一致；保持各专精确认过的特例。
- **Lua：** 是否混入技能选择和治疗评分；是否存在有证据的高频重复扫描、分配或多余定时器。必要的显示计算和普通聚合不自动算违规。检查最长 1 秒兜底及 AuraContainer 原生绑定豁免、秘密值路径和失效清空。
- **配套一致性：** 按变更需要读取 [像素审查](../pixwow-pixel-audit/SKILL.md) 和 [文档审查](../pixwow-docs-audit/SKILL.md)；发现复杂布局须追共享 helper，不止看 cells 文件名。

## 主 agent：核实与报告

核实每条发现，合并重复项，保留能复现或由源码支持的结论；不能不经核实自动接受 subagent 的修复建议。开发流程只修复本次问题与必要阻塞项，修复后针对性复核。

报告包含范围、按影响排序的发现、位置和证据、影响、最小建议及未验证事项。区分“无发现”和“未完成审核”。委派工具不可用时如实报告独立审核未完成，不改称自查为独立审核，也不无限重试。
