# WoW API 与解析约定

## API 选择与版本

当前五项目声明版本为 `12.1.0.69933`，Interface 为 `120100`。涉及 API、事件、模板或原生生命周期时，先核对相邻 `wow-ui-source` 的版本与实际定义、调用示例；更新客户端版本时重新检查受影响接口。

检查 API 是否 Deprecated，以及是否有 `C_` 命名空间替代。已有现代接口时直接使用，不依赖可关闭的旧全局兼容别名。例如防骑专精使用 `C_SpecializationInfo.GetSpecialization()`；旧全局 `GetSpecialization` 是否存在取决于兼容层。

`UnitHealthPercent(unit, usePredicted, curve)` 如无明确例外，第二个参数使用 `true`，布局文档注明预测生命口径；不能把预测生命描述成未经预测的当前生命。

## 秘密值与显示

只有普通值才能直接比较、运算、索引和控制 Lua 分支。潜在秘密值交原生显示接口消费；不从颜色通道、文字、槽位可见性或布局反读秘密数据进行业务判断。保留必要的 `issecretvalue` 检查顺序，某个单位、版本或返回值可计算的经验不能推广为通用保证。

当前项目的技能充能灰度显示使用 `string.format → SetText`；光环层数使用 `SetApplicationCount` 与共享 `CountFormatter` 的原生绑定，规则文字在初始化时生成。用户已确认当前技能层数、光环层数及现有字形／灰度实现可用，不能仅因涉及秘密值就反复报告为未验证路线。不要将这一经验扩展到任意秘密返回值，也不要把光环绑定误写成 Lua 读取秘密层数后直接运算。

光环筛选、显隐和持续时间更新沿用原生容器。当前上游的 `SetAuraSlotCandidateFilters` 内部会执行 `UpdateAllAuras`，调用后不立即重复刷新；同 token 换人仍要重设筛选条件。

## 像素异常兜底

### 布尔 Cell

当前五项目的 `Context.readBooleanCell` 只有 `Cell.is_white` 成立时返回 true；纯黑以及其他未被判为纯白的输入均返回 false。这是已确认的设计，保持此行为，不新增三态结果或因非黑非白而抛异常。

业务通常使用正向 true 条件允许技能，false 使这些条件不成立。这个约定不代表所有异常像素都会阻止全部动作：如缺宠判断和某些暂停门控采用反向条件，必须按实际谓词解释。保留已确认的现有策略，不因假设局部遮挡而自行增加全局校验规则。

### 吸收 ValueBar

比例为 `白色像素数 / (白色像素数 + 黑色像素数)`；分母为零时返回 `0.0`，是吸收量的设计兜底。全黑为 0、全白为满量程，其他颜色不计入分母。兜底为零不证明游戏中的实际吸收为零，也不改为解码异常。

### IconTile

黑名单／白名单等图标匹配只要求同一客户端中同一图标在不同位置的采样一致，不追求跨客户端、字体或渲染环境的全局指纹一致性。不为跨客户端指纹差异主动引入新的识别系统。纹理相同不保证技能 ID 唯一，解释图标匹配时保留这个含义。

## 同一药水的不同品阶

圣光潜力 `241308`、`241309` 是同一药水的两个品阶，用户确认共用冷却。库存按物品 ID 分别查询，不能因名称或冷却相同就把单个 ID 的计数当作两个品阶的总数。

血 DK 和惩戒参考本地 Shigure 的 `Fuyutsui/core/spells.lua` 中 `GetItemRemainingTime` 及 `UpdateItemCooldown`：按每个 ID 查询 `C_Item.GetItemCount` 和 `C_Item.GetItemCooldown`。本项目不含普通银行、材料银行、账号银行或使用次数计数；任一品阶有库存、冷却启用并结束即输出药水可用。缺失冷却数据或冷却禁用不算就绪，不额外检查 IsUsableItem。

保留已有宏中的两个 ID 及先后顺序，不新增像素槽位，也不由 Python 分别选择品阶。此约定只应用于明确支持的药水，不据此批量扩展其他物品。

## 审查时如何使用这些约定

本文件记录用户确认的当前设计与使用经验，不是本轮工具运行或游戏验收报告。若实现符合约定且没有新的实际故障证据，不重复提出“false／0 兜底必须改错”“跨客户端图标必须一致”或“计数显示路线完全未验证”。有具体偏离时指出偏离和影响；环境变化时说明变化的范围。
